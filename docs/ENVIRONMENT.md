## Загрузка и обязательные ограничения

`core/settings.py:4` вызывает `load_dotenv()` без явного пути и без `override=True`: используется автоматический поиск python-dotenv, уже заданное окружение обычно имеет приоритет. Рабочая директория штатных команд — корень приложения. Отдельное исключение: исторический `scripts/deploy_paused.py` явно загружает выбранный `.env` с `override=True`; это не обычный запуск.

Настройки создаются при импорте точек входа. Импорт `desktop.main` или `webapp.server` не является безопасной проверкой конфигурации: одновременно создаются хранилища и SQLite-сервисы. Ошибочные числовые строки могут сорвать запуск; строгой проверки всех переменных и допустимого имени сети пока нет.

Категории: **REQUIRED** — нужны соответствующему процессу; **OPTIONAL** — есть значение по умолчанию; **MAINNET-SENSITIVE** — влияют на доступ или операции с реальными средствами; **TEST-PAPER** — относятся к режимам, но не заменяют изоляцию тестов; **OPERATIONS** — эксплуатация. Категории могут пересекаться.

## Полный список переменных приложения

Все 13 полей настроек читаются в `core/settings.py:25–39`; `WEBAPP_URL` отдельно в `desktop/main.py:39`. В таблице указаны именно значения по умолчанию в коде, а не содержимое рабочего `.env`.

| --- | --- | --- | --- |
| `TELEGRAM_API_ID` | REQUIRED: bot; MAINNET-SENSITIVE | `0` | Telegram application ID, целое число. Бот отвергает ноль при запуске (`desktop/main.py:40`). Не является Telegram user ID. |
| `TELEGRAM_API_HASH` | REQUIRED: bot; MAINNET-SENSITIVE | пусто | Telegram application hash. Проверяется непустое значение. Секрет, не публиковать. |
| `TELEGRAM_BOT_TOKEN` | REQUIRED: bot/web-auth; MAINNET-SENSITIVE | пусто | Авторизация бота и проверка подписи Mini App `initData` (`webapp/server.py:75–101`). Секрет. |
| `TELEGRAM_OWNER_ID` | OPTIONAL | `0` | Поле парсится, но действующих проверок доступа по нему нет. **Не работает как allowlist или защита «только владелец».** |

| `MAX_LEVERAGE` | OPTIONAL; MAINNET-SENSITIVE | `20` | Целое, минимум `1`. В копировании учитывается минимум плеча источника, серверного, пользовательского и биржевого лимита (`core/trading_engine.py:91–99`). | `WATCH_INTERVAL` | OPTIONAL; OPERATIONS | `3` | Секунды, минимум `1`. Пауза **после полного цикла** копирования; сетевые вызовы и обработка других пользователей прибавляются. Не гарантирует обновление каждого аккаунта каждые три секунды (`desktop/main.py:671–692`). |

Иных читаемых приложением переменных окружения при статической инвентаризации не обнаружено; SSH/systemd/shell имеют собственное окружение за пределами этого списка.

## Что означает безопасный пример

[`../WalletHunterV05_final/.env.example`](../WalletHunterV05_final/.env.example) намеренно содержит `HL_MODE=TESTNET`, `AUTO_TRADING=false`, пустые секреты и недействительный домен-заглушку. **TESTNET в примере отличается от опасного значения MAINNET по умолчанию в коде.** Пример не готов к запуску и не меняет существующий `.env`.

Для разработки нужны отдельные тестовые учётные данные и изолированный временный `data/`. Нельзя копировать рабочую Telegram session, мастер-ключ или API key финансируемого аккаунта в тесты. Даже `AUTO_TRADING=false` не делает импорт/вызов всех API безопасным: `webapp/server.py:522–559`, `:777–838` создают signing client для ручных действий и подтверждённых AI-форм независимо от этого флага. TESTNET — другая сеть, PAPER — способ исполнения; это разные понятия.

При необходимости новый Fernet-ключ можно сгенерировать стандартным `Fernet.generate_key()` в отдельной безопасной процедуре. **Не генерировать новый ключ поверх рабочего `MASTER_KEY` при рестарте или восстановлении.** Ротация с перешифрованием здесь не реализуется.

## Политики, которые не являются env-переменными

- Фиксированная расчётная доля источника — `1/3` (`core/trading_engine.py:116–117`); пустой слот не должен передавать её другому источнику. Полнота обеспечения занятым капиталом пока не гарантирована: P1-02.
- Независимый AI-вход: `ENTRY_MARGIN_FRACTION=.10`, `MAX_ENTRY_LEVERAGE=40` в `core/ai_entry_policy.py`; фактический размер также ограничивают настройки/биржа/доступность. Реальные формы требуют отдельного подтверждения; виртуальный трейдер остаётся PAPER.
- Анализ вмешательства в существующую позицию: `ROE ≤ −40%` в `core/ai_rescue_policy.py`. В `core/ai_policy.py` есть отдельные ограничения дополнительного бюджета `50%` доли источника и до четырёх доборов. Исследовательский порог `.60` не доказывает вероятность прибыли и не даёт автономного разрешения на реальную сделку.
- Риск-профиль, выбранные кошельки/AI-слот, язык, уведомления и флаги режимов сохраняются в профиле, а не в новых выдуманных env-переменных. Изменение `.env` не заменяет проверку профиля.

## Зависимости и воспроизводимость

`requirements.txt` содержит диапазоны, не lock-файл: Telethon `>=1.42,<2`; python-dotenv `>=1.0,<2`; hyperliquid-python-sdk `>=0.21,<1`; eth-account `>=0.13,<1`; cryptography `>=43,<48`; requests `>=2.31,<3`; FastAPI `>=0.115,<1`; Uvicorn `>=0.30,<1`; Pydantic `>=2.9,<3`. `requirements-dev.txt` включает runtime requirements и HTTPX `>=0.28,<1`.

Фаза 0 дополнительно фиксирует `requirements.lock`, `requirements-dev.lock` и `requirements-build.lock` с версиями/хешами; именно они, а не широкие входные диапазоны, задают воспроизводимую установку. Область платформ и версии — в [DEPENDENCIES.md](DEPENDENCIES.md) и [`dependency-inventory.json`](dependency-inventory.json). Отчёт изолированных тестов — в [PHASE0.md](PHASE0.md). Это не доказательство версий на сервере. Для будущего восстановления надо сохранить также версию Python/OS, фактически разрешённые зависимости и используемую версию SDK; переноса одного `requirements.txt` недостаточно для идентичной среды.

Локальная Windows-проверка не равна выполненному Linux CI. Linux-исполнение, отдельные browser-аудиты и production-инвентаризация не подтверждаются этими документами; подготовительная фаза остаётся частичной по этим внешним проверкам.

Незакрытые вопросы конфигурации, секретов и режимов перечислены в [`PHASE1_FINDINGS.md`](PHASE1_FINDINGS.md). В этой фазе их runtime-поведение не меняется.
